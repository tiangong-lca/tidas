本页帮助第一次接触 LCA 数据的读者理解本站用词。中文名称是本站为方便阅读采用的表达，不宣称为 ILCD 官方中文译名；正式含义以欧盟委员会联合研究中心（JRC）的 [ILCD Handbook: General guide for Life Cycle Assessment](https://publications.jrc.ec.europa.eu/repository/bitstream/JRC48157/ilcd_handbook-general_guide_for_lca-detailed_guidance_12march2010_isbn_fin.pdf) 和相关数据格式说明为准。

## LCA 研究中的常用概念

### 生命周期评价（LCA）

研究一个产品或服务从原料获取、生产和使用到最终处置等生命周期阶段的资源使用、排放及潜在环境影响。LCA 不是单一碳排放数字，而是一套先确定目的与范围，再做清单、影响评价和结果解释的方法。

### 目的与范围

先说明为什么开展研究、给谁使用、研究什么以及计算到哪里。目的会影响后续的数据需求、系统边界、影响评价和结论表达。

### 功能单位

所有结果共同对应的服务量，也是不同方案能够比较的基础。它应说清提供什么功能、多少、达到什么质量以及持续多久，例如“向指定地区低压用户交付 1 kWh 交流电”。

### 基准流（Reference flow）

为了实现一个功能单位，产品系统实际需要的产品或服务数量。部分资料称“参考流”；本站首次出现时会把两种说法并列，避免误认为两个概念。

### 系统边界

说明哪些生命周期阶段和过程计入研究、哪些不计入，以及排除的理由。

### 产品系统

为完成某项功能而相互连接的一组单元过程。过程之间通过产品、废物或其他流连接起来。

### 单元过程与过程数据集

**单元过程**是能够单独记录投入和产出的最小活动，例如一次发电或运输活动。**过程数据集**是保存某项活动及其投入、产出、时间、地点、技术和资料来源的数据记录；二者不一定完全等同。TIDAS 的过程文件接近后一个含义，更多字段见 [ILCD Process data set format](https://eplca.jrc.ec.europa.eu/LCDN/downloads/ILCD_Format_1.1_Documentation/ILCD_ProcessDataSet.html)。

### 交换（Exchange）

一个过程中某项输入或输出的记录。交换把过程与产品流、废物流或基本流连接起来，并写明数量和单位。

### 基本流

直接从自然环境进入技术系统，或从技术系统直接排回自然环境的物质或能量，例如开采的资源和排放到空气中的物质。

### 生命周期清单（LCI）

记录产品系统各过程使用了什么、产出了什么、排放了什么，以及各有多少。英文为 *life cycle inventory*。

### 生命周期影响评价（LCIA）

把生命周期清单中的资源使用和排放换算成气候变化等潜在环境影响指标。LCIA 结果是指标，不是对实际环境后果的直接预测。

### 数据质量与代表性

说明数据是否足够完整、可靠，并且像研究所需的技术、地区和年份。技术、地理和时间代表性应分别说明，还可能包括精度、不确定性和方法适宜性。

### 独立专业评审

由具备相应能力且与研究保持所需独立性的人，按明确范围和方法检查数据、方法、解释和报告。自动格式检查不能代替独立专业评审。

## TIDAS 和数据工具中的用词

### TIDAS

一套用于保存、检查和交换 LCA 数据的结构与工具规则。它规定过程、流、单位、来源及其引用怎样整理，但不替代研究目的、系统边界、分配、数据质量和评审等专业判断。

### JSON 与 JSON Schema

**JSON** 是保存结构化数据的文件形式。**JSON Schema** 是可由软件执行的一组检查规则，用来判断必填字段、数据类型和允许取值等是否符合 TIDAS 的数据结构。

### 电子交换格式

让一套软件或数据库把数据完整交给另一套系统的文件组织方式。TIDAS 与 eILCD 可以在工具明确支持的范围内转换；成功转换不表示两者所有方法含义完全相同。

## 不要混在一起的检查结果

- **结构检查通过**：文件能读取，字段、类型和局部规则通过 JSON Schema。
- **文件和引用完整**：所需文件存在，ID、版本及跨文件引用能够对应。
- **可按指定格式交换**：使用明确版本的转换规则执行成功，并检查了输出。
- **数据质量已有说明**：完整性、代表性、不确定性等已有资料和判断；这不是 Schema 能自动得出的结论。
- **已完成独立评审**：记录了评审人员、范围、方法和结论；它不同于自动校验。
- **具名合规声明**：只有明确指出所依据的体系及版本，并检查其方法、质量、文档和评审要求后才适用。不能只因为格式检查通过就写“合规”。

更多关于 ILCD 格式检查、文档完整性和评审字段的边界，可参阅 JRC 的 [ILCD data set documentation guidance](https://eplca.jrc.ec.europa.eu/uploads/QMS_H08_ENSURE_ILCD_GuidanceDocumentationLCADataSets_Version1-1Beta_2011_ISBN_clean.pdf)。
