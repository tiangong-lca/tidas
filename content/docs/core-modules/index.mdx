TIDAS 把常见的 LCA 数据整理成相互关联的文件。本页先解释这些数据记录了什么，再说明工具可以检查到哪里。遇到不熟悉的概念，可随时查看[术语与缩写](/zh/docs/glossary/)。

## LCA 数据怎样关联

- **过程数据集（Process dataset）**：记录一项生产或服务活动，以及它使用什么、产出什么、在哪里和何时发生、资料来自哪里。
- **交换（Exchange）**：把过程与流（Flow）连接起来。流可以是产品或废物，也可以是直接从自然环境取用或排回自然环境的**基本流**。
- **流属性（Flow Property）与单位组（Unit Group）**：说明数量如何计量和换算，例如质量、能量或体积。
- **来源（Source）与联系人（Contact）**：记录资料依据和责任信息；分类表帮助不同数据使用相同名称和编号。
- **生命周期影响评价方法（LCIA Method）与生命周期模型（Life Cycle Model）**：保存计算环境影响和连接产品系统所需的引用。

## 数据会经过哪些检查

1. **文件能否读取**：JSON 语法是否正确。
2. **数据结构是否正确**：JSON Schema 检查必填字段、数据类型、允许取值和单个文件中的关系。
3. **文件之间是否完整一致**：检查目录、ID、版本和跨文件引用能否对应。
4. **能否按指定格式交换**：需要转换为 eILCD 等电子交换格式时，还要按所选转换规则实际执行转换并查看结果。
5. **是否适合研究目的**：系统边界、功能单位、分配、技术/地理/时间代表性、不确定性和评审状态需要另行说明和判断。

## 工具能检查什么、不能检查什么

TIDAS 工具可以检查文件格式、字段和引用，也可以执行受支持的格式转换。这些自动检查通过，不能证明 LCA 方法选择正确、数据质量足够，也不能代替独立专业评审。

只有在明确写出所依据的体系和版本，并完成该体系要求的质量、方法、文档与评审检查后，才适合给出具名的合规声明。“结构检查通过”“文档完整”“数据质量说明”“已完成独立评审”应分别记录，不能合并成一个笼统状态。

## 从一个最小数据包开始

1. 建立一个[过程数据集](/zh/docs/core-modules/schema/schema-content/json-schema-processes/)。
2. 加入它引用的流、流属性、单位组、联系人和来源。
3. 用 `tidas validate --schema-only` 查找字段和结构问题。
4. 再运行完整的 `tidas validate`，检查数据包和跨文件引用。
5. 根据数据用途补充数据质量说明、方法判断和所需评审；如需留存工具版本，参见[进阶说明](/zh/docs/tool/)。
