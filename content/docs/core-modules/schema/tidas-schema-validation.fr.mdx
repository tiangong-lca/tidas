---
title: "Validation de schéma"
---

Les structures de données TIDAS sont définies avec JSON Schema. Le point d’entrée de validation par lot pris en charge est `tidas validate` dans la CLI Rust unifiée. Il utilise hors ligne les ressources JSON Schema, XSD ILCD et de règles intégrées et vérifiées dans la version installée, sans arborescence source externe ni environnement Python. Enregistrez la version binaire et les empreintes réelles avec `tidas version --format json` ; les [`tidas-tools` Releases](https://github.com/tiangong-lca/tidas-tools/releases/latest) font autorité pour les publications.

---

## Valider un paquet JSON TIDAS

```bash
tidas validate ./tidas-package \
  --input-format tidas-json \
  --issues ./issues.jsonl \
  --format json
```

- Le répertoire d'entrée positionnel contient les sous-répertoires de catégories TIDAS canoniques.

- `--issues` écrit de manière atomique le flux complet déterministe de problèmes JSONL.

- `--format json` maintient stdout vers un rapport stable lisible par machine; les diagnostics et la progression utilisent stderr.

- `--report <path>` persiste de manière atomique le rapport complet.

### Exécuter uniquement le diagnostic Schema

```bash
tidas validate ./tidas-package \
  --input-format tidas-json \
  --schema-only \
  --format json
```

`--schema-only` vérifie uniquement la couche Schema. Il ignore les contrôles complets du paquet, des références et du profil de conversion ; il ne prouve donc pas la convertibilité eILCD et ne constitue pas une preuve complète de conformité.

## Valider un paquet XML ILCD

```bash
tidas validate ./ilcd-package \
  --input-format ilcd-xml \
  --issues ./issues.jsonl \
  --format json
```

Le validateur utilise uniquement les ressources XSD intégrées et vérifiées pour l'intégrité dans le binaire et réutilise les contextes de validation hors ligne.

## Inspecter les empreintes du validateur

Enregistrez le protocole de validation, le moteur et les empreintes de verrouillage de schéma avant une exécution CI reproductible ou par lot :

```bash
tidas validate --describe --format json
tidas version --format json
```

Le protocole `document-validation-batch.v1` valide exactement les documents manifestes et produit des événements de problèmes déterministes plus un hachage de preuve final :

```bash
tidas validate ./batch-root \
  --protocol document-validation-batch.v1 \
  --input-manifest ./document-validation-batch.v1.jsonl \
  --events ./validation-events.jsonl \
  --format json
```

## Vue d'ensemble du contenu de validation

La validation TIDAS combine deux types de vérifications :

### 1. Validation de structure (Standard JSON Schema)

- Vérification des champs manquants (requis)

- Vérification de la correspondance des types de champs (chaîne, nombre, etc.)

- Vérification des valeurs de champs par rapport aux définitions (format, enum, etc.)

- Support de la résolution de références inter-modules ($ref)

### 2. Logique de paquet et de classification

Pour les structures de classification comme les flux, processus, sources :

- **Vérification de hiérarchie** : Vérifier que la séquence `@level` est correcte

- **Règles de code** : Vérifier que les éléments enfants utilisent les codes des éléments parents comme préfixe

- **Correspondance d'industrie de classification de processus** : Vérifier que les codes d'industrie respectent la logique de mappage des normes nationales

- **Vérifications de référence et de paquet** : Appliquer les contraintes inter-modules et de paquet à partir des ressources verrouillées

---

## Sortie des résultats de validation

Le rapport normal contient des comptes de problèmes bornés et le hachage du flux de problèmes; `--issues` conserve chaque problème. Les problèmes de document représentent un scan complet, tandis que le rapport et le statut de sortie distinguent les problèmes de données des échecs de protocole ou d'exécution. L'automatisation devrait analyser le rapport stable `--format json` au lieu de faire correspondre du texte lisible par l'homme.
