Les outils en ligne de commande TIDAS sont distribués sous la forme d'un unique
exécutable Rust multiplateforme nommé `tidas`. Ce site documente la sémantique
stable des commandes ; la source faisant autorité pour les versions, les archives
par plateforme, les sommes de contrôle et les prérequis d'installation est la
[dernière version GitHub](https://github.com/tiangong-lca/tidas-tools/releases/latest).
Ainsi, aucun numéro copié dans la documentation ne dérive de la version réellement publiée.

---

## 🚀 Obtenir et vérifier une version

Les utilisateurs choisissent dans la dernière version l'archive précompilée
correspondant à leur système et à leur architecture, puis la vérifient avec le
fichier `SHA256SUMS` de cette même version. Une formule Homebrew ou un manifeste
Winget joint décrit l'archive et son empreinte ; les notes de version restent la
référence pour savoir si un tap externe ou un paquet Winget Community est disponible.

Les développeurs qui installent depuis crates.io doivent d'abord vérifier les
exigences publiées concernant Rust et les dépendances natives, puis utiliser la
version choisie dans Releases :

```bash
# Copier la version depuis Releases/latest et retirer un éventuel préfixe v.
TIDAS_VERSION="<release-version>"
cargo install tidas --version "$TIDAS_VERSION" --locked
```

Après l'installation, il ne faut pas déduire la version du nom d'une archive.
Inspectez le binaire réellement résolu par le terminal et les empreintes de ses
ressources intégrées :

```bash
tidas version --format json
```

Cette sortie est le moyen privilégié de confirmer les versions effectives de la
CLI et du contrat, ainsi que les empreintes JSON Schema, XSD, XSLT et méthodologiques.

## 🔍 Sept sous-commandes unifiées

- `tidas convert` convertit entre les parcours pris en charge de JSON TIDAS et de XML eILCD.

- `tidas import` intègre les sources EcoSpold, SimaPro, openLCA ou ILCD prises en charge au flux unifié.

- `tidas export` crée des ZIP TIDAS/ILCD déterministes à partir d'enregistrements de base de données et d'un stockage d'objets optionnel.

- `tidas validate` valide hors ligne le JSON TIDAS ou le XML ILCD et peut écrire un flux déterministe de problèmes JSONL.

- `tidas release` valide, convertit et construit des paquets de publication reproductibles.

- `tidas ruleset` inspecte les ensembles de règles fournis avec l'exécutable.

- `tidas version` rapporte les empreintes du binaire, du contrat, des ressources et de l'environnement d'exécution.

`tidas <command> --help` fait autorité pour les options actuelles. Dans les
automatisations, privilégiez les sorties structurées, fichiers de rapport et
limites de ressources pris en charge par chaque commande.

## ✅ Comprendre les niveaux de validation

`--schema-only` n'est qu'un diagnostic structurel de Schema. Ce n'est ni un
contrôle de cohérence complet, ni la preuve qu'un jeu de données peut être
converti en eILCD. Avant livraison, exécutez le `validate` ordinaire et, lorsque
le flux cible exige eILCD, testez réellement le parcours de conversion applicable :

```bash
tidas validate ./tidas-package --schema-only --format json
tidas validate ./tidas-package --issues ./issues.jsonl --format json
tidas convert ./tidas-package --output ./eilcd-package --to ilcd --format json
```

Autres points d'entrée courants :

```bash
tidas convert ./eilcd-data --output ./tidas-package --to tidas --format json
tidas import ./database.zip --output ./imported --target both --format json
```

La CLI intègre les ressources JSON Schema, XSD, XSLT et méthodologiques requises
à l'exécution et en vérifie l'intégrité. L'utilisation normale ne demande donc
pas de copier des ressources depuis d'anciens répertoires source. Pour un audit
ou une reproduction, conservez la sortie d'empreintes de
`tidas version --format json`.

## Migrer depuis les commandes héritées

Les anciens exécutables autonomes et la disposition des arguments du paquet
Python ne sont plus le parcours actif documenté par ce site :

| Ancien point d'entrée | Point d'entrée de la CLI unifiée |
| --- | --- |
| `tidas-validate` / `validation.py` | `tidas validate` |
| `tidas-convert` | `tidas convert` |
| `tidas-import` | `tidas import` |
| `tidas-export` | `tidas export` |

Les entrées sont généralement positionnelles, les sorties utilisent `--output`
et la direction de conversion utilise `--to ilcd|tidas`. Consultez
`tidas <command> --help` pour chaque étape migrée au lieu de conserver les anciennes options.
