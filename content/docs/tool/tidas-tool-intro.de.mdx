Die TIDAS-Kommandozeilenwerkzeuge werden als eine plattformübergreifende,
in Rust entwickelte ausführbare Datei namens `tidas` bereitgestellt. Diese
Website beschreibt die stabilen Befehlssemantiken. Maßgeblich für Versionen,
Plattformarchive, Prüfsummen und Installationsvoraussetzungen ist die
[neueste GitHub-Veröffentlichung](https://github.com/tiangong-lca/tidas-tools/releases/latest),
damit keine kopierte Versionsnummer von der tatsächlichen Veröffentlichung abweicht.

---

## 🚀 Veröffentlichung beziehen und prüfen

Endanwender wählen in der neuesten Veröffentlichung das vorgefertigte Archiv für
ihr Betriebssystem und ihre Architektur und prüfen es mit den `SHA256SUMS`
derselben Veröffentlichung. Eine beigefügte Homebrew-Formel oder ein
Winget-Manifest beschreibt das zugehörige Archiv und dessen Hash; ob ein externer
Tap oder ein Winget-Community-Paket verfügbar ist, steht in den Release Notes.

Wer aus crates.io installiert, prüft zuerst die dort genannten Anforderungen an
Rust und native Abhängigkeiten und verwendet dann die in Releases ausgewählte Version:

```bash
# Version aus Releases/latest kopieren und ein führendes v gegebenenfalls entfernen.
TIDAS_VERSION="<release-version>"
cargo install tidas --version "$TIDAS_VERSION" --locked
```

Nach der Installation sollte die Version nicht aus einem Archivnamen abgeleitet
werden. Stattdessen werden die tatsächlich aufgerufene Binärdatei und die
Fingerabdrücke ihrer eingebetteten Assets geprüft:

```bash
tidas version --format json
```

Diese Ausgabe ist der bevorzugte Nachweis für die wirksamen CLI- und
Vertragsversionen sowie die Fingerabdrücke von JSON Schema, XSD, XSLT und Methodik.

## 🔍 Sieben einheitliche Unterbefehle

- `tidas convert` konvertiert zwischen unterstützten TIDAS-JSON- und eILCD-XML-Pfaden.

- `tidas import` überführt unterstützte EcoSpold-, SimaPro-, openLCA- oder ILCD-Quellen in den einheitlichen Ablauf.

- `tidas export` erzeugt deterministische TIDAS-/ILCD-ZIP-Dateien aus Datenbankeinträgen und optionalem Objektspeicher.

- `tidas validate` prüft TIDAS-JSON oder ILCD-XML offline und kann einen deterministischen JSONL-Problemstrom schreiben.

- `tidas release` prüft und konvertiert Daten und erstellt reproduzierbare Veröffentlichungspakete.

- `tidas ruleset` zeigt die mit dem Programm ausgelieferten Regelsätze an.

- `tidas version` gibt Fingerabdrücke von Binärdatei, Vertrag, Assets und Laufzeit aus.

Für die aktuellen Optionen ist `tidas <command> --help` maßgeblich. In der
Automatisierung sollten die vom jeweiligen Befehl unterstützten strukturierten
Ausgaben, Berichtsdateien und Ressourcengrenzen verwendet werden.

## ✅ Validierungsstufen verstehen

`--schema-only` ist lediglich eine strukturelle Schema-Diagnose. Die Option ist
keine vollständige Konsistenzprüfung und beweist nicht, dass sich ein Datensatz
in eILCD konvertieren lässt. Vor der Auslieferung ist das normale `validate`
auszuführen; verlangt der Zielablauf eILCD, muss zusätzlich der passende
Konvertierungspfad erprobt werden:

```bash
tidas validate ./tidas-package --schema-only --format json
tidas validate ./tidas-package --issues ./issues.jsonl --format json
tidas convert ./tidas-package --output ./eilcd-package --to ilcd --format json
```

Weitere häufige Einstiegspunkte sind:

```bash
tidas convert ./eilcd-data --output ./tidas-package --to tidas --format json
tidas import ./database.zip --output ./imported --target both --format json
```

Die CLI enthält die zur Laufzeit benötigten JSON-Schema-, XSD-, XSLT- und
Methodik-Assets und prüft deren Integrität. Bei normaler Verwendung müssen daher
keine Assets aus alten Quellverzeichnissen kopiert werden. Für Audit und
Reproduktion sollte die Fingerprint-Ausgabe von `tidas version --format json`
aufbewahrt werden.

## Von früheren Befehlen migrieren

Die früheren Einzelprogramme und das Argumentlayout des Python-Pakets sind nicht
mehr der von dieser Dokumentation unterstützte Weg:

| Früherer Einstiegspunkt | Einstiegspunkt der einheitlichen CLI |
| --- | --- |
| `tidas-validate` / `validation.py` | `tidas validate` |
| `tidas-convert` | `tidas convert` |
| `tidas-import` | `tidas import` |
| `tidas-export` | `tidas export` |

Eingaben sind meist positionsgebunden, Ausgaben verwenden `--output`, und die
Konvertierungsrichtung wird mit `--to ilcd|tidas` festgelegt. Vor der Migration
jeden Schritts ist `tidas <command> --help` zu prüfen, statt alte Optionen zu übernehmen.
