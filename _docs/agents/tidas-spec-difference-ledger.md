## W6a/A09 website schema disposition

This is an evidence ledger, not an approval to switch the website. The machine-readable report is [`tidas-spec-difference-ledger.json`](./tidas-spec-difference-ledger.json), generated by `scripts/ci/compare-tidas-spec.mjs` from one explicit `tidas-spec` source tree. It compares parsed JSON Schema structures and records every differing JSON pointer, category, and abbreviated value/hash. `oneOf`/`anyOf`/`allOf`, `required`, and `enum` are compared with stable identities or set semantics so taxonomy insertion does not create positional noise.

## Current qualified comparison

- Website base: `1de417637cc78f5b1673adf9129acf0db69409eb`.
- `tidas-spec` candidate: `6fb497bad562125ccc0c00a803351207b9ed438f`; package version `0.1.0`; manifest SHA-256 `fe82b77411e2a134469b206367556a52bf6be80419fcbc0749a2439dc785631b`.
- 19 website files are present: 9 differ from the 18-file normative candidate, 9 are byte/structure-identical, and `tidas_data_types_viewer.json` is explicitly a viewer projection outside the normative archive.
- 1,192 differing semantic JSON locations are recorded. The high count is expected for the existing product/category labels and category-shape differences; it is not collapsed into a claim that the site is equivalent.
- The report remains `unresolved`: no item is treated as a spec correction, website-local presentation adapter, or retained historical asset until the spec/content owner and site owner record a decision with positive and negative fixtures.
- The current tracked versioned output still verifies the earlier W4 archive identity (`archiveSha256=921a0ffa0d3703bc2d9bd8a5bbb02d327be7746177487af8245ac2788a7cf91e`, `manifestSha256=646699afaf5c3bdfa6ccfe5153b11d6978ee62227fdace19f3b7715b59c50010`). This is retained historical output, not evidence that the unpublished W5 candidate has been adopted.

Observed classes include dataset-category wrapper/definition changes, flow required-name differences, elementary/product/process taxonomy membership and labels, and the extra viewer-only projection. These labels describe observed constraint locations; they do not decide which side is correct.

## Reproduction

From the website repository root:

```bash
node scripts/ci/compare-tidas-spec.mjs \
  --spec-root ../tidas-spec \
  --site-commit 1de417637cc78f5b1673adf9129acf0db69409eb \
  --check _docs/agents/tidas-spec-difference-ledger.json
```

The comparator fails if the selected source tree, file set, parsed content, or report metadata changes. A changed report requires re-running semantic review; it is not a reason to silently regenerate public assets.

## W6b handoff gate

W6b may proceed only after every entry in the JSON report has an owner disposition, a constraint-level positive/negative fixture, and an independently reviewed compatibility decision. Until then, the current public schema URLs, historical files, viewer projection, and site build remain the retained combination. No production deployment, URL cutover, spec publication, or root pointer update is implied by this ledger.
